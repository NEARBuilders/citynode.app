# Tests

Two loops. Use the fast one unless the change is about rendered pages,
SSR/hydration, or a real auth session.

Judgement — when to write a test at all, which layer, what the parent framework
already covers, and how to write a regression test that fits this setup — lives
in [`docs/agents/testing.md`](../docs/agents/testing.md). This file is the
operational view (commands, prerequisites, costs).

## Which harness?

| Changed | Run | Cost |
|---|---|---|
| `api/src/**` logic | `pnpm --dir api run test` (in-process oRPC, PGlite) | seconds, no Docker |
| `plugins/<name>/**` logic | `pnpm --dir plugins/<name> run test` (PGlite + mocked FastKV) | seconds, no Docker |
| `ui/src/**` components/lib | `pnpm --dir ui run test` (vitest + jsdom) | seconds, no Docker |
| runtime-map generator | `pnpm run test:runtime-map` | <1s |
| rendered page / SSR compose / hydration / session cookie / nav | `pnpm run test:regression:browser` | minutes, Docker + full stack |
| the same against the CSR (no-SSR) compose path | `pnpm run test:regression:browser:dev:csr` | minutes, Docker + full stack |

Root shortcuts: `pnpm test` (fast suites + runtime-map), `pnpm run test:api`,
`pnpm run test:integration`.

## Fast suites

- **API** — `api/tests/unit` + `api/tests/integration`. Integration tests boot
  the real oRPC router in-process on an ephemeral port; auth context is injected
  via headers and DAO verification is mocked. DB is in-memory PGlite unless
  `TEST_DATABASE=postgres`.
- **Plugins** — real tests live in `plugins/<name>/src/__tests__/`. The
  `plugins/<name>/tests/` directories contain only framework-owned `types.d.ts`
  — do not look for tests there.
- **UI** — colocated `ui/src/**/*.test.tsx`. A global setup regenerates the
  gitignored `*.gen.*` artifacts before the suite.

## Browser regression (Playwright)

```bash
pnpm run test:regression:browser:install   # once: Chromium (+ system deps)
pnpm run test:regression:browser           # dev:ssr (default)
pnpm run test:regression:browser:dev:csr   # dev:csr
pnpm run test:regression:browser:all       # both, serially
```

Run one spec or filter tests:

```bash
pnpm exec playwright test -c tests/regression/browser/playwright.config.mjs \
  specs/onboarding.spec.ts
REGRESSION_MODE=dev:ssr pnpm exec playwright test \
  -c tests/regression/browser/playwright.config.mjs --grep "sign in"
```

Boot the stack without Playwright (debugging):

```bash
pnpm run regression:dev:ssr   # or regression:dev:csr
```

### Prerequisites

- Docker running. Preflight runs `docker compose up -d --wait`; test Postgres
  services are `postgres-api-test` (5434) and `postgres-auth-test` (5435).
- `.env.test` (generated by `bos dev`); the guard refuses to run if a DB URL or
  `BETTER_AUTH_SECRET` resolves to the dev values. Override deliberately with
  `REGRESSION_ALLOW_DEV_DB=1`.
- A resolved config (`.bos/bos.resolved-config.json`) — `pnpm run types:gen`.

### Cost and lifecycle

- The Playwright `webServer` boots the full `bos dev` tree with `BOS_NO_WATCH=1`
  and a **5-minute** budget; `reuseExistingServer: false`, so every invocation
  pays the boot. One spec is not cheaper than all of them.
- `workers: 1`, `fullyParallel: false`, `retries: 1`. A stall watchdog fails the
  suite after ~2 minutes of zero progress and prints a runner snapshot.
- CI: the browser suite is currently **non-gating** (`continue-on-error`) until
  upstream everything-dev#531 lands. A green CI run does not prove E2E; run it
  locally when your change touches pages or sessions.

### Stack and variant

The framework vocabulary is Stack (`start` | `dev`) × Variant (`ssr` | `csr`).
In this consumer repo only **`dev`** exists — `start:*` boots the parent's image
fixture, which is not buildable here (image validation is the deploy train's
smoke gate). Both variants are wired: `dev:ssr` and `dev:csr`. The `backcompat`
mode in `regression-env.mjs` is implemented but has no script.

## What covers what

- `api/tests/integration/*` — contract behaviour through the real router
  (permissions, proposals, onboarding-code redemption, org/team access).
- `tests/regression/browser/specs/*` — end-to-end user journeys against a real
  browser, real sessions, and the composed remote auth UI (login, onboard,
  settings, admin, orgs, discovery).
- **Auth fixtures** — `tests/regression/lib/auth-test-instance.ts` mints
  sessions against a **frozen snapshot** of the upstream auth schema
  (`tests/regression/fixtures/auth/`). Refresh that snapshot when the platform
  pin bumps; otherwise fixtures drift from the running remote plugin and fail
  like local bugs.
