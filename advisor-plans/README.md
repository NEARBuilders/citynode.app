## Verification gates common to every plan

- `bun typecheck` (all workspaces; also regenerates gitignored `.gen.ts` type files)
- `bun lint` (biome, must exit 0)
- Per-workspace suites per each plan's command table
- After touching `packages/every-plugin` or `packages/everything-dev`: `bun run build` in that package before integration tests / CLI smoke (stale-dist is a known crash class; plan 013 adds automated detection)
- Host-touching plans (003, 004, 009): `bun run --cwd host test` — 2 `runtime-remote` failures are known deploy-gated (production v1 remotes vs v2 host); they pass after `bos publish --deploy`. Never chase them in these plans.

## Findings considered and rejected

- `module-federation.service.ts` remote-constructor `any`s (~lines 144-182): genuine untrusted-module boundary with explicit error guards — not worth typing.
- Dev-server CORS `*`: dev-only local surface, standard convention.
- `secrets.service.ts` regex interpolation of secret keys: keys are host-controlled config, not request data; would become a finding if `SecretsConfig` ever becomes user-writable.
- `ui/src/routeTree.gen.ts` casts: generated file.
- Vendored `packages/better-near-auth` test `any`s: test-only mocks in a vendored package.
- Full error-taxonomy merge (host `FederationError` ≡ every-plugin `ModuleFederationError`): host tags are load-bearing in SSR tests/logs; only the unwrappers and interceptor options are consolidated (plan 009). Revisit with a log-consumer inventory.
- Consolidating `host/rsbuild.config.ts`'s shared-deps copy into every-plugin (plan 010 keeps it out of scope): different merge semantics with bos.config shared maps; recorded as deferred follow-up in plan 010's maintenance notes.
