Add a `deploy` section to `bos.config.json` and a working Cloudflare R2 CDN deploy pipeline (Phases 0–2 of the pluggable CDN plan, `plans/infra/cloudflare-cdn-alchemy.md`). `deploy.cdn: "zephyr" | "cloudflare"` selects the provider (default `zephyr` — existing deploys unchanged); optional `deploy.cloudflare` settings (`hostname`, `bucket`, `zone`) default to `cdn.<domain>` and a derived bucket name, with staging-aware domain resolution and legacy `ci.railway.service` mapping. With `cdn: "cloudflare"`, `bos publish --deploy` fails fast with a `bos cdn login` hint when no Alchemy credentials are detected, then builds without Zephyr, installs a pinned Alchemy sandbox into `.bos/alchemy/` (isolated Effect 4 peer resolution), generates an `alchemy.run.ts` that provisions the R2 bucket (custom domain + CORS) and uploads each workspace's dist via Alchemy Actions (stdin is forwarded so the one-time state-store bootstrap prompt works), computes SRI locally, and writes the R2 URLs into `bos.config.json` before the FastKV publish. New `bos cdn login` command installs the sandbox and runs the alchemy OAuth flow so the sandbox CLI path never needs to be memorized. Zephyr remains a selectable fallback; the sandbox collapses into a direct dependency with the Effect 4 migration (`.scratch/cloudflare-cdn/issues/01-effect-4-migration-and-alchemy-desandbox.md`).
